# پایگاه دانش دستیار هوشمند

دستیار فقط از فایل‌های `.txt` همین پوشه جواب می‌دهد و هر پاسخ را با ارجاع به یک منبع نشان می‌دهد.
اگر پاسخ در این فایل‌ها نباشد، به‌جای حدس‌زدن می‌گوید اطلاعات ندارد و مشتری را به «تماس با ما» می‌فرستد.

## قالب یک فایل

```
# خطی که با # شروع شود یادداشت شماست و خوانده نمی‌شود
title: عنوانی که کنار پاسخ به‌عنوان منبع نمایش داده می‌شود
url: /faq
type: faq
status: published

متن پاسخ، با جمله‌های ساده.
```

- `title` و `url` الزامی‌اند. `url` باید مسیری از خود سایت باشد (با `/` شروع شود)، نه آدرس بیرونی.
- `type` اختیاری است: `faq` (پیش‌فرض)، `policy`، `service`، `pricing` یا `contact`.
- `status` اختیاری است: `published` (پیش‌فرض) یا `draft`. **پیش‌نویس روی فایل می‌ماند ولی دستیار آن را نمی‌گوید.**
  اطلاعاتی را که هنوز مطمئن نیستید (قوانین ایمنی، قیمت، شماره تماس) `draft` نگه دارید.
- بین خط‌های بالا و متن باید یک **خط خالی** باشد. هر متن حداکثر ۴۰۰۰ نویسه.
- نام فایل (بدون `.txt`) شناسهٔ موضوع است؛ عوض کردن نام یعنی حذف یک موضوع و ساختن یکی دیگر.

## بعد از تغییر فایل‌ها

دستیار فایل‌ها را هنگام راه‌اندازی API می‌خواند. برای اعمال فوری و دیدن گزارش (کدام فایل استفاده شد، کدام نه و چرا):

```bash
docker compose exec api python -m davos.tools.sync_knowledge
```

فایلی که اشتباه دارد استفاده **نمی‌شود** (نسخهٔ قبلی‌اش هم برداشته می‌شود تا نیمه‌ویرایش‌شده گفته نشود) و دلیلش در گزارش
می‌آید. بقیهٔ فایل‌ها بدون مشکل کار می‌کنند.

## وضعیت فعلی

نه فایل منتشر شده‌اند و همه از حرف‌های خود مالک‌اند: `booking` (رزرو آنلاین از سایت یا تلفنی)، `capacity` (قانون صندلی عقب)، `single-seater` و `two-seater` (شرایط سنی، قد، گواهینامه و استثنا)، `prices`، `working-hours`، `club` (هنوز عضویت فعال نیست)، `support` و `group-sessions` (قانون گروه و تقسیم سانس‌ها).

**عددهایی که در پنل مدیریت عوض می‌شوند را در این فایل‌ها ننویسید:** تعداد خودروهای تک‌نفره و دونفره، قیمت‌ها، روزهای بدون رزرو، مدت نگه‌داشتن خودروها برای پرداخت و باز/بسته بودن رزرو آنلاین. دستیار این‌ها را برای هر پرسش زنده از «تنظیمات رزرو» پنل مدیریت می‌خواند (حداکثر ۳۰ ثانیه بعد از ذخیره)، و حساب سانس‌های یک گروه و مقایسهٔ سن، قد، روز، ساعت و وزن را هم خود سیستم انجام می‌دهد، نه مدل.

دو فایل `clothing` و `contact-details` هنوز `draft` هستند چون اطلاعاتشان
تایید نشده (لباس مناسب و آدرس متنی پیست). بعد از تایید هر کدام، متن را درست کنید و خط `status: draft` را به
`status: published` تغییر دهید.

قوانین سنی خودرو تک‌نفره (`single-seater.txt`) عمداً به شکل «پله» نوشته شده و سن‌ها و قدهای نمونه یکی‌یکی آمده‌اند؛ مدل
کوچک عدد را خوب مقایسه نمی‌کند ولی کلمه را خوب تطبیق می‌دهد. اگر عددی را عوض کردید، همه جای آن فایل را عوض کنید و سؤال‌های
متداول سایت (`frontend/src/content/site.ts`) را هم هماهنگ کنید. دو مورد را مالک مشخص نکرده و دستیار پیش‌فرض گذاشته است:
عدد ۱۱ برای «زیر ۱۱ سال به هیچ عنوان رانندگی نمی‌کند» و «سن دقیقاً ۱۵ سال را هنگام رزرو با مجموعه هماهنگ کنید».

نکته: تا وقتی مجموع متن‌های منتشرشده کم است (حداکثر ۱۲ فایل و ۸۰۰۰ نویسه)، دستیار **همهٔ آن‌ها را برای هر پرسش** به مدل
می‌دهد تا پرسش‌های محاوره‌ای هم جواب بگیرند. پس هر فایل را مستقل و کامل بنویسید (مثلاً جایگزین مجاز را در همان فایل
بگویید). اگر پایگاه دانش بزرگ‌تر شد، خودکار به جست‌وجوی مرتبط‌ترین متن‌ها برمی‌گردد.

قیمت‌ها (`prices.txt`) واحد را «هزار تومان» فرض کرده‌اند (۷۹۰ = ۷۹۰ هزار تومان؛ «۱ تومن» = یک میلیون تومان). اگر واحد
دیگری است، همان‌جا اصلاح کنید.

توجه: پاسخ «سؤال‌های ساده و کلی» دربارهٔ ساعت کاری، رزرو/شماره تماس، ظرفیت، قیمت‌ها و باشگاه مستقیماً از خود همین فایل‌ها (بدون مدل و کش) داده می‌شود و با **عنوان** (`title`) پیدا می‌شود. عنوان این پنج فایل را عوض نکنید (`ساعت کاری`، `نحوه رزرو نوبت`، `خودروها و ظرفیت هر سانس`، `قیمت‌ها`، `باشگاه مشتریان داوس`)؛ اگر عوض شد یا فایل `draft` بود، پرسش به مدل می‌رود و تست `test_shipped_assistant_content.py` خطا می‌دهد.

حجم: مجموع متن‌های منتشرشده حدود ۷۲۰۰ نویسه است و سقف «ارسال کامل به مدل» ۸۰۰۰ نویسه است. اگر متنی اضافه کردید و از ۸۰۰۰ گذشت، دستیار به جست‌وجوی مرتبط‌ترین متن‌ها برمی‌گردد و کیفیتش برای پرسش‌های محاوره‌ای کم می‌شود؛ سقف را در `AssistantPolicy.whole_knowledge_max_chars` می‌شود بالا برد.
